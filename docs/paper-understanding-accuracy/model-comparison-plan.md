# 候选模型对照方案

基线在实际选段和人工充分选段两组中，均把 BPR 已明确的段落二值码误判为待核查。B 组还出现 TQA Top-1 百分点算错。候选对照仅拟验证这些问题是否随模型改变。

候选为 TokenDance 公开目录中的 `deepseek-v4-pro`。目录返回 HTTP 200，列出 OpenAI Chat Completions 文本协议和 1,048,576 token 上下文。已只读核对项目仍使用现有 TokenDance Chat Completions 接入和原有凭据变量。候选账户可用性、响应模型、实际可用输出上限和结构表现需真实请求验证，公开上下文长度不能证明可输出同等数量的 token。当前配置仍用于 Flash 验收。

公开目录每百万输入 token 标价 8.1–9，输出 24.3–27，按该目录人民币计价口径保守采用 ¥9／¥27。按 104,000 字节请求上限再加 4,096 保护余量及 8,192 输出上限，6 次网络尝试的保守预留约 **¥7.164288**。实际结算、时段和缓存折扣以服务商回执为准。

如获新增授权，使用单独隔离运行和账本。以本轮 B 组 D1、D2、B1、B1f、B2、G1 的原始请求为固定基线，只替换请求模型字段。每题一次，共 6 次，保持同一公开材料、用户问题、证据编号、`json_object`、温度 0.2 和 8,192 输出预算。保留传输或结构失败，不自动补发。B1f 采用已归档的同一用户问题和同一原文，两个模型均不接收旧助手结论。需记录网关实际返回模型、服务端可用输出、缓存、推理用量和端到端耗时，避免将不同缓存或路由条件解释为模型差异。

评阅时随机交换匿名回答顺序，按冻结判据人工逐题核对。记录关键事实准确性、是否标明材料边界、引文准确性、可理解性、格式成功率、耗时和估算费用。匿名结果与原始回执均保留。模型互评可辅助定位，最终评分由人工核对原文。

新增授权范围仅为同一 TokenDance 端点上的 `deepseek-v4-pro` 和上述 6 个已归档公开材料请求。本轮未发起候选调用。
