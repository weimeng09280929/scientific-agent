## 1. 交付结论与范围

本轮统一了实际主应用的导航、对话输入、阶段提示、文献阅读和方案审阅。离线夹具中的主要路径通过，适合继续进行**本地体验与用户反馈**。这不表示新手已认可，也不表示方案科学正确。

**真实模型端到端仍未通过。** 第八步 A 的 OpenAlex 超时、arXiv 重定向及随后 HTTPS 修正尚未经真实重验；本轮未追加任何公网检索或付费／真实模型调用，不能用 UI 和离线成功覆盖该结论。

- `/`、`/workspace` 仍加载 `web/static/index.html`、`app.js`、`conversation-home.js`，新增共享样式 `ui-experience.css`；没有改造未使用的 `workspace.html/workspace.js`，没有新框架或独立演示站。
- 产品最多到 DESIGN；会话隔离、材料指纹、明确采纳、版本链、上传请求身份和审计机制沿用原实现。
- 没有批量改名、删除、归档或向真实用户项目写入测试数据，没有提交或推送。

## 2. 修改前的问题与本轮处理

| 走查问题 | 处理 |
| --- | --- |
| 常用资料入口在历史列表之后，项目越多越难找 | 当前项目资料固定在上方，最近对话与项目共用下部原生滚动区 |
| 首页、输入和设置占用过多空间，空会话输入框浮在中间 | 保留简短开场；设置按需展开；消息区伸展，输入固定在布局底部而非覆盖正文 |

| 新研究默认提交 computer_science，像是用户已选择 | 不再默认选择；首次发送缺领域时保留草稿、展开设置，明确确认后才创建 |
| 教学与普通方案预览不同，长正文和提示重复 | 统一五项摘要及“打开方案”；完整正文复用同一材料审阅组件，原回复可按需展开 |
| 文献页仍露出旧笔记编辑器和三步流程条 | 笔记统一从上方入口进入；阅读页也用紧凑、可展开的四阶段导航 |
| 文献首屏充斥技术字段、旧配额和高级筛选 | 默认搜索、年份、标题和阅读范围；高级条件、历史审计与技术详情折叠 |
| 同名方案的展开状态可能相互影响 | 按真实记录／建议／论文 ID 记忆展开状态，不按标题恢复 |
| 新回复保存后、页面材料尚未加载时已允许继续操作 | 完成请求后等待消息和共享材料交付，再开放发送；核对最新预览绑定最新建议 |

## 3. 统一交互规则

### 导航和名称

侧栏为“产品及收起按钮 → 新建对话 → 当前项目资料（文献、方案、笔记、更多）→ 最近对话 → 项目 → 帮助”。下部历史区可滚动，上方资料不会被长列表挤走。没有项目时资料入口不可用，不自动创建。

最近对话与项目默认各至多 5 条。项目展开先 10 条，再每批 5 条；最近对话每批增加 5 条，可搜索、收起。项目内会话仍按需读取。会话切换保留当前已展开窗口（重载窗口上限 50）；刷新后可恢复当前 URL 的项目／会话，列表重新从默认窗口读取。没有一次请求所有聊天历史。

项目仍按既有真实活动时间排序；对话仍按会话 `updated_at` 排序，这包含消息与设置更改，并非仅最后一条消息时间。只读浏览不更新活动时间。项目管理、固定 ID 多选、确认摘要、受保护项目和可恢复归档沿用原接口，真实项目清理由用户自行明确选择。

历史数据名称完全不批量改写，只在窄位置省略。完整名称可通过标题提示、键盘可达的操作菜单和详情查看；触屏菜单始终可见。新项目／会话只从首条输入提取可读短主题，不增加模型调用；不能可靠提取时使用可编辑的“新研究／研究讨论 · 日期”。完整原始需求仍在用户消息中。不是通过截断持久化历史名字来追求长度。

### 输入、进度与任务

- 常用输入操作为文字、资料、发送；指导方式、进入阶段、目标、归属与领域在讨论设置中。普通研究和教学输入布局相近，教学仅保留简短离线提示。
- 文本框适度增高并有最大高度；保留草稿、Ctrl/Cmd+Enter、输入法组合保护、同请求去重和切换后的归属校验。
- 新研究必须明确确认现有九领域中的一个。领域未定时不建项目、不调用模型；老草稿里隐式遗留的 computer_science 不当作用户已确认。已有项目的领域不被改写。后端枚举、默认契约和数据库结构未扩大。
- 四阶段统一为“明确条件 → 了解研究现状 → 确认研究问题 → 形成并审阅方案”。当前主线和可审阅状态来自 `product_stage`、`product_boundary`、`workflow.flow.planReady`；进入阶段、用户正在浏览的页面不代表阶段完成。
- 阅读页的四阶段导航默认一行，展开后显示已有材料／待复核等服务端状态。明确条件是讨论入口，不虚构“已完成条件确认”。历史执行图保留在任务活动中，不再冒充第二条产品主线。
- 检索任务跟随对应消息显示真实状态和操作；来源、统计、耗时、错误放详情。未关联到当前已加载消息的任务保留可访问入口，不被丢弃。轮询保留展开与滚动位置，不伪造百分比、剩余时间或内部推理步骤。
- 阅读历史时不强制滚到底部，通过“查看最新消息”定位。切换页面不取消服务端任务，也不自动重发。

### 文献与方案

文献首屏突出导入、搜索、年份、标题／作者、与正式问题的关系、阅读范围。关系使用已有正式关联或原有说明，不把会话猜测变成已确认事实。正文开头节选明确区别摘要，失败提示保留。技术字段、原审计、期刊分区／IF 等移入详情或高级筛选；历史统计明确不是当前对话任务范围，去掉写死来源配额。

上传仍使用第八步 A 的 `request_id`、文件摘要与原请求查询，不因布局变动丢失幂等和恢复。上传文本没有 PDF 依据时不展示凭标题寻找 PDF 的入口；合法已有论文的 PDF 操作保留，是否实际可下载仍需原接口验证。标题支持键盘展开，PDF 按钮不再嵌在另一个可交互按钮内。

方案统一为“简短摘要 → 打开完整方案 → 审阅／修改／采纳／下载”：

1. 摘要包含研究问题、方法、判断方式、条件、待确认事项。
2. 普通对话、教学对话和研究方案详细页打开同一个审阅组件。桌面可扩大阅读，窄屏全宽显示且有“返回对话”，Escape 和焦点约束可用。正文不再套小块独立滚动区。
3. 草案、正式版本、历史版本、待复核和教学标记保留。展开阅读不自动采纳；缺依据、材料变化和跨项目引用仍由服务端拒绝。
4. 修改条件先准备可编辑讨论请求，不偷偷改 brief。修订有可比较结构时展示实际变化段落；旧版无结构或无法可靠比较时明确说明，不能用版本号增加冒充改善。
5. 下载仍位于对话顶部，使用服务端实际目录与精确版本 URL，区分当前正式方案、未采纳草案、其他版本和历史产物。没有产物时不触发生成。
6. Word/PDF 复杂公式与表格格式限制没有在本轮全面修复；Markdown 保留公式源码，页面公式渲染与打印能力沿用既有实现。

## 4. 最小接口及数据兼容变化

唯一新增后端能力是最近会话的只读搜索，不另建会话或主线数据：

```http
GET /api/conversations/recent?limit=5&offset=0&q=联邦
GET /api/conversation-capabilities
```

能力响应新增 `conversation_search: true`。`q` 可选、至多 200 字符，匹配会话标题及项目显示名／主题／编号。先在每个库内筛选有界元数据，再统一排序分页；`%`、`_` 等按普通搜索字符处理。保留 `conversations`、`next_offset`、`current_conversation`、`unavailable_projects`、`sort_basis` 及所有旧调用方式。GET 不建库、建表、迁移或导入历史；不可读项目如实报告。

旧主服务未声明搜索能力时只禁用该新增搜索并说明需更新后端，不把任意 404 都解释为版本问题，也不静默回退为混合聊天。项目管理、归档、产物和所有消息／采纳协议不变。

### 过程中出现的问题没有当作成功略过

- 实际发现过空会话输入框浮起、重复摘要、同名版本展开串联、新回复材料尚未交付就能发送、旧笔记编辑器挤压列表；已修复并对相关实际操作复测。
- 一次重跑会话浏览器失败于“找不到重试按钮”：该隔离夹具按固定文本只注入一次失败，复用已消费该失败的服务不会再次失败。保留失败记录，核对夹具后使用新临时实例复验；没有靠延长超时或删除失败／重试断言通过。
- 新增搜索测试曾在折叠后的异步列表响应前立刻断言，改为等待真实列表收起；笔记检查曾命中隐藏兼容 DOM 与正文两个节点，改为明确核对正文。关键行为断言保留。
- 项目导航测试的分页等待改为每次等待真实条数增长，避免在首批尚未返回时再次读取旧分页位置；没有提高结果上限来掩盖遗漏。

## 6. 五分钟人工体验路线

需要**已加载新版后端的本地实例**。本轮隔离服务验收后关闭；不建议在真实网关未核实前随手发送普通研究请求。

1. 首页查看三种开场，点击后观察输入可编辑、没有立即创建项目。展开讨论设置，确认指导方式、进入阶段和领域。
2. 进入“案例体验 · 离线可用”，选联邦学习 v1.1.0，明确条件后打开一份案例文献；找到标题、阅读范围和来源。
3. 选择问题并明确“采用这个问题”。随后打开方案，查看五项摘要和完整正文，试一次“修改条件”。
4. 核对修改与未确认事项，明确采纳，再从顶部“下载当前产物”下载正式版本。教学完成不表示结论已验证。
5. 收起材料，切换同项目另一段对话或打开项目。检查上方资料、下方历史分组、完整名称菜单和草稿是否符合预期；将窗口缩窄再试返回与下载。

用户体验反馈：**待用户确认**。重点请用户判断是否看得懂当前阶段、能否找到材料／采纳／下载、窄屏输入是否舒适、名称是否容易区分。自动化不能代用户签收。

## 7. 生效状态、已知限制与停止点

- 8001 未自行启停。验收期间只读检查原 PID 30416 的 `/api/conversation-capabilities` 不含 `conversation_search`、`background_plan`、`upload_request_identity`、`call_audit`，当时**未加载本轮及第八步 A 的对应后端能力**。2026-10-22 最终复核时 8001 已无监听、原 PID 不存在，HTTP 连接被拒绝；没有足够证据判断其退出原因，不能归因于本轮修复。共享磁盘上的静态页面已更新不等于后台曾更新。完整体验需用户之后授权启动新版主服务；本轮没有代为启动或重启。
- 隔离验收使用 8055—8059 和临时目录，结束后关闭；没有把临时项目填入真实项目列表。
- 已实现但尚未验证：真实手机软键盘／设备、其他浏览器与读屏器、全格式 Word/PDF、真实网络和网关内容质量、长时间负载。高对比度遵循原生策略，但不是一次完整无障碍认证。

- 本轮不含：新案例、新领域、账号收费、多人权限、公网部署、实验、训练、结果或论文生成。真实链路仍有来源阻断，不能宣传可直接公网发布。
