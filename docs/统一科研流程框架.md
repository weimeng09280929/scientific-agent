# 统一科研流程框架

## 一、固定下来的产品路径

项目与范围 → 文献及研究现状 → 确认研究问题 → 确认方法与验证方案 → 外部执行、回填结果 → 记录研究判断 → 整理成果。

这是一条可以暂停、修订和恢复的研究主线，不是一次点击后无人参与的自动论文生成。文献、方法与写作允许提前整理；没有结果时停留在等待状态。运行失败、负面结果与无法定论均可如实记录。

用户只需要理解三个层次：

| 层次 | 内容 | 作用 |
| --- | --- | --- |
| 材料来源 | 论文、候选思路、研究缺口、方法文档、实验任务与已有结果 | 原件保留，可能由旧任务、模型或用户产生；不自动当成研究结论 |
| 当前主线 | 问题 → 方案 → 结果 → 判断 → 写作骨架 | 经用户明确确认，保存依赖、选中问题与方案；从这里继续研究 |
| 后台材料任务 | 原有检索、思路生成、设计、任务规划和写作节点 | 沿用已有执行图、检查点与人工节点，不取代用户选择的主线 |

不扩大领域：仍是计算机系统、AI、计算机安全与隐私。实验仍为外部执行，本次未新增自动训练能力。

## 二、数据与代码职责

```text
浏览器页面、科研指导、继续按钮
                  │
             FastAPI 接口
                  │
    WorkspaceService（版本校验和事务写入）
        ├─ workflow.py：统一主线、阶段与下一步的只读推导
        ├─ materials.py：既有材料适配、来源指纹、变更识别
        ├─ schema.py：问题/方案/结果/判断/骨架、服务端主线选择
        └─ 项目 SQLite
              ├─ research_workspace.v1：用户确认的主线与对话
              ├─ papers / ideas / experiments / artifacts：既有材料
              └─ pipeline.context.v1：后台执行光标与恢复信息

后台 Pipeline → 既有材料库 → 用户核对并关联 → 当前主线
```

- `core/workspace/workflow.py` 是主线判断的权威来源。浏览器旧版纯 JS 推导仅保留为旧后端兼容，不再承担新接口的主线裁决。
- `Workspace.focus` 持久保存当前问题和方案。旧项目缺少该字段仍可读取；只有一个候选时可无歧义展示，有多个时要求明确选择，不猜测跨问题关系。
- `WorkItem.source_ref` 保存来源类型、稳定编号和内容指纹；来自旧材料的记录不与来源重复计算为独立实验。
- 原数据库、产物与检查点不批量重写，不把所有旧 Claim 自动升级，也不在读取页面时启动模型或训练。

## 三、新旧材料如何衔接

1. 在研究问题页展开“已有材料”，可将候选思路或文献问题确认关联为研究问题。
2. 在方案与实验页，将方法文档或实验任务关联到当前问题。任务来源保留，不要求重新生成。空方法正文不能关联。
3. 有结果后可手动登记，或关联同一任务已有的结果。尚未执行的 planned 任务不能当成结果；旧 completed 记录没有有效指标也不能当作实测结果。
4. 对关联实验任务的方案手动登记结果时，工作台记录与原 `experiments` 行在同一个 SQLite 事务内更新，避免出现两个不同版本的事实。
5. JSON 批量回填仍兼容原任务。若已有关联的结果，来源指纹变化会让该结果及其下游判断、提纲待复核；核对后可更新关联并保留历史版本。

关联是明确写入动作，需要确认、当前工作台版本和最新来源指纹。同一来源不重复创建有效记录，不允许把实验 B 的结果关联到实验 A 的任务方案。方法文档和实验任务属于不同来源层次，系统不猜测它们一定等价。

手动修订已关联材料时保留旧记录和 `supersedes_id`，新内容按用户修订记录处理；不能继续假装它与旧任务协议完全一致。要比较新的实验协议，应明确创建相应方案及任务，不沿用旧结果冒充新验证。

## 四、继续任务的决策

优先处理仍在运行的后台任务或真实人工确认节点，不重复启动，也不自动批准。重启后保留的人工节点需要恢复确认。

有已确认问题后，“继续”根据主线打开：选问题/方案、修订待复核记录、填写结果、记录判断或整理成果。只打开登记页不会执行实验。没有确认问题但已有思路时，先进入已有材料确认；不是再次检索整项研究。

如需继续原后台生成任务，在任务进度中明确选择“继续后台材料生成”。该操作可能调用模型，并沿用原执行检查点；它不会悄悄替换已确认的研究问题。后台完成状态与科研判断状态分开显示。

## 五、真实性与修订边界

- 保存方案不等于已运行；保存结果不等于独立复现；用户判断不等于科学结论已被系统证实。
- 运行失败或无法定论不能支持正向或反向实证判断，只能保留无法定论。
- 一份方案对应一个研究问题，一条结果对应一份方案；一条判断不能混用不同方案的结果。
- 来源变更、记录修订会使下游待复核，不删除原记录，不覆盖旧指标，不自动重跑实验。
- 演示数据、预期展示与真实结果分开。本次已有的预期稿仍是写作骨架，0 条实际结果，不升级为项目实证完成。
- 真实模式禁止使用 `force_writing` 绕过结果审核生成实证稿件。可以先整理背景、方法、写作骨架与局限。

## 六、接口契约

| 接口 | 职责 |
| --- | --- |
| `GET /api/projects/{id}/workspace` | 主线、记录、材料关联目录及统一 workflow |
| `GET /api/projects/{id}/status`、`/dashboard` | 相同的主线选择、阶段、下一步；轮询响应不重复发送来源正文 |
| `PUT /api/projects/{id}/workspace/focus` | 校验并保存当前问题/方案，拒绝跨问题选择 |
| `POST /api/projects/{id}/workspace/link-material` | 明确确认后关联来源，指纹或版本过期返回冲突 |
| `POST /api/projects/{id}/workspace/items` | 保存或修订记录，关联任务的结果在同事务同步原实体 |
| `POST /api/projects/{id}/resume` | 返回统一下一步；必要时恢复后台任务，否则只导航到当前主线 |
| `POST /api/projects/{id}/experiments/backfill` | 兼容批量来源结果导入，不替代用户对主线依据的复核 |

综合报告现在同时包含既有产物与当前主线记录，来源、待复核状态和演示标记随导出保留。

## 七、后续扩展边界

后续功能应增加材料来源、领域规则、指导策略或执行器能力，不另建一套项目阶段与继续逻辑。新的用户操作应先通过 WorkspaceService 的契约和版本校验，再扩展页面；不能在前端私自把状态改成完成。

当前仍不承诺：用户填写的数字已经独立验证、所有论文全文已读、模型建议必然可实现、公众多租户上线安全已完成、外部检索服务永不失败。

测试使用临时目录和软件夹具，不访问真实训练环境。自动重启主服务曾受环境限制；如旧进程尚在运行，需正常重启后端才能加载新接口，单纯刷新网页不能热更新 Python 模块。
