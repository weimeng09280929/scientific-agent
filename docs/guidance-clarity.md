## 最终规则

稳定身份仍为“科研指导伙伴——帮助科研新手理解问题、核对依据，逐步形成自己的研究问题和方法草案。”

- 首次出现关键领域术语／缩写时，先解释它是什么、解决什么问题，再给正式名称；按当前学科解释，必要时给具体例子，不用另一串术语替代，不确定不编定义。普通词与已经解释清楚的内容不反复列术语表。
- direct 模式减少入门铺垫，但不假定熟悉另一学科；明确要求专业／简短时压缩。入门模式更多原因和例子，证据要求相同。
- “没听懂、不是我的领域、再简单一点”等偏好实际进入生成器：重新解释当前难点，换具体例子，不只换词复述，不追问专业问卷、不推进阶段。输出校验同时移除结构化追问／推荐／动作／草案，不能仅靠提示词维持停下行为。自然语言解释是否足够好仍需真实质量验收。
- 新环节或请用户完成任务时，自然说明做什么、为什么此时做、需用户提供什么、预计得到什么；同环节普通问答不重复流程，未知可留空，讨论不等于确认问题、证明创新或完成实验。
- 选项按需提供，与 actions 合计仍最多四项；只解释／暂停可没有选项。explanation 必须与 label/content 相符，只描述讨论预期，不是额外执行授权。

最终实际 system/context 示例见 [生成器捕获记录](guidance-clarity/contexts.json)，包含单一稳定身份、两次连续困惑偏好与实际历史。未更改原回答正文去伪造教学结构。

## 字段、页面与真实点击行为

示例（人工设计的离线结构样例，不是真实模型评价）：

```json
{
  "label": "比较条件",
  "content": "请比较哪些条件可能影响材料强度，先不保存。",
  "explanation": "列出可能影响比较的条件，得到待核对清单。"
}
```

网页直接显示三层：标题“比较条件”；“讨论预期：列出可能影响比较的条件，得到待核对清单”；“发送内容：请比较哪些条件可能影响材料强度，先不保存。”说明使用 textContent，不能注入网页／地址。

explanation 的长度通过 schema 校验；对显式承诺自动执行／保存及保证科研结果的部分模式拒绝交付，属于有限保护，**不声称能自动证明说明与 content 的全部语义一致**。正常“不会自动保存”经正向回归，避免把否定限制当成执行承诺。即使说明错误，也不会被拼入 content 或用于工具授权；真正操作仍走原服务端动作校验。

| 入口 | 点击实际行为 | 明示预期／限制 |
| --- | --- | --- |
| 首页第一次做研究 | 填入开场文字及原模式／起始环节 | 发送后讨论兴趣和条件，逐步整理方向，不自动发送 |
| 首页已有方向 | 填入开场文字 | 发送后讨论方向与资料需求，不直接检索 |
| 首页已有问题 | 填入开场文字 | 发送后核对问题和方法；满足依据条件后才可生成待审阅草案 |
| 推荐回复 | 仅把原 content 作为下一条消息发送 | 预期是讨论结果，说明不增加授权；有草稿先明确选择，保留原输入 |
| 步骤选择／下一环节 | PATCH 原 discussion_step | 只切换讨论起点，不自动发送、检索或确认材料 |
| 当前步骤讨论入口 | 发送该步骤原讨论文字 | 预计获得该环节解释／讨论稿，不是完成该阶段 |
| 当前检索步骤入口 | 原范围核对与明确确认流程 | 确认后才检索，可能有调用费用 |
| 准备方案请求 | 打开问题／方法请求设置 | 核对并发送才生成草案，采纳另需确认 |
| view_references | 原动作校验后打开已有引用 | 不重新检索；以实际阅读范围为准 |
| open_plan | 原动作校验后打开已有正式方案 | 不生成新版本 |
| open_settings | 原动作校验后打开讨论设置 | 不发送消息或调用模型；浏览器实际点击验证 |
| adopt_suggestion | 原动作接口再次校验后采纳 | 将草案写为正式记录，保留依据变化／权限校验 |
| start_search | 原动作校验及范围确认后检索 | 明确确认、原预算和限制保持 |

所有模型动作说明按允许的 action.type 固定映射；没有增加模型可指定的动作、URL 或保存能力。

## 预期教学例子与后续真实体验

以下均为人工预期示例，**不是模型实测输出**：

- 材料比较中的混杂因素：“另一个因素可能同时影响比较分组和结果，让人误判原因，这叫混杂因素。例如两种材料加工温度也不同，就不能把强度差异全归于材料。”
- 跨领域问 RAG：“先找相关资料，再让模型参考资料回答，这类方法叫检索增强生成（RAG）。它用于减少只凭模型内部信息回答的问题，但检索到资料不保证答案正确。”
- 评价指标：“把想比较的效果变成能核对的量或标准，这叫评价指标。材料强度与检索准确性需要不同标准，不能把同一指标套给所有学科。”
- 步骤目的：“现在先列比较条件，是为了避免把其他变化误当作方法作用。告诉我哪些条件已知；不确定可留空。我们先得到一份待核对清单，不启动实验。”

少量真实验收建议：材料背景用户问混杂因素并连续反馈没听懂；非计算机用户问 RAG 缩写；用户说已有方向后核对一步的目的；展示三个选项请用户解释区别再选一个。每项看完请用户用自己的话复述概念、说明当前步骤为何需要、说清点击的预期与不会发生的操作。若只能重复模型原句，或误以为已保存／已实验，应判教学不通过。

拟使用仓库既有真实体验模型 `deepseek-v4.1-flash-1017`，不切换提供商；建议最多 **4 次真实网络尝试，合计费用上限人民币 1 元**，每次输出上限 4096 token，失败／重试同样计入。实际执行前应核对当前模型、单价与费用保护能否覆盖请求；不足则停止。此为下一轮待明确授权的建议，**本轮未启用，也不挪用之前 2 元授权**。
