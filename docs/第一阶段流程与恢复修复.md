# 第一阶段：流程衔接与中断恢复

本次保留现有导航、论文库、灵感笔记、头像和写作页面结构，不新增领域、不代跑实验。

## 已调整

- 新建页粘贴编号后“打开并继续”实际调用统一继续接口，不再只切换项目。
- 已有项目列表、总览和进度页使用相同继续逻辑：选题探索回到选题，正在运行的不重复启动，待确认的打开人工节点，等待外部结果的去回填，已结束的查看成果。
- 选择项目同步保存当前编号与页面 URL，刷新不会回到 URL 中上一个项目。切换时清空前一个项目的页面缓存。
- 保存运行模式和检索偏好；进程重启后按执行材料恢复。发现已保存在磁盘但未登记到内存的项目时，可按编号重新加载，不要求新建替代项目。
- 选题转主流程时跟踪新线程，避免误判中断并清除有效人工等待。失败保留当时材料与失败节点，只有明确回滚才恢复检查点。
- 恢复实验审核不再用其他旧任务覆盖未导出的规划。等待结果只检查当前任务集合，不因其他历史任务未完成而卡住。
- 修正结果报告误把实验对象传入指标检查的问题。结果支持、反驳或无法定论均保留原判断，不要求创新成立才能整理已有实测结果。
- 写作恢复检查实验记录是否变化：未变化则保留草稿与确认位置；变化或旧版缺少指纹时先保留旧草稿再复核。终稿后更新结果会提醒人工核对，不静默改写终稿。
- 稿件与修改意见按最新版本分组统计，写作导航不再只统计手工提纲。总览新增简短说明与“当前任务和下一步”，并区分后台主题和手动研究记录主线。

## 验证边界

新增临时 SQLite、真实编排节点和离线模型/检索夹具测试，覆盖五个阶段人工确认中断、失败节点重试、线程交接、外部结果回填与稿件保存；浏览器测试覆盖编号继续、项目切换与刷新、人工确认不重复启动及说明书展示。不使用真实科研数据，不代表独立验证科研结论。

中断时尚未完成的外部请求可能需要重试；不能保证外部模型服务恢复后一定成功。损坏或丢失的数据库、缺少必要材料的历史项目，以及因范围限制停止开放的非计算机领域，不能承诺自动恢复完整研究。当前仍为单进程服务，不是分布式任务队列。
