## 2. 用户实际看到的四阶段

| 阶段 | 现在做什么、为什么做 | 用户得到什么 |
| --- | --- | --- |
| 明确条件 | 具体情境与一个关注点选择，避免从一大堆论文或大表单开始 | 可修改的讨论兴趣；条件明确标为教学设定，不是用户事实 |
| 了解研究现状 | 阅读通俗的已知/待核对概览，点击“查看这三篇文献”到正常材料卡 | 了解资料实际上支持什么、阅读到哪里；看资料不等于采纳或发现创新 |
| 确认研究问题 | 比较两个候选，选择后复述具体问题，单独点击“采用这个问题” | 项目自己的正式问题记录；只看候选或解释不会确认 |
| 形成并审阅方案 | 读五项摘要，打开完整方案，调整范围，审阅新稿，明确保存与下载 | 问题、方案、来源及待讨论事项；没有实验结果或科学结论验证 |

推荐默认路线安排一次真实范围调整，但不以“是否点过每份资料”锁定科学进度。用户可以跳过操作教学、返回查看、换候选、自由提问或停下来。不同问题和范围实际使用不同的 `method_details` 和正文，而不是只换标题。

## 3. 两个案例的完整路径

### 联邦学习：计算研究

1. 新对话 → 案例体验 → 联邦学习 v1.1.0 → 开始体验。情境是入门者想了解设备数据差异下的方法比较，不假设用户已有设备或数据。
2. 选“先学怎样公平比较两种方法”。也可选数据差异关注点；后续候选排序和解释会呼应选择，仍可改选。
3. 读 FedAvg、FedProx、SCAFFOLD 的已知与未知范围；点“查看这三篇文献”，打开一张普通文献卡，看到摘要阅读范围及与问题的关系。外部原文可选，不影响离线流程。
4. 比较“两方法公平比较”和“FedAvg 随数据差异的稳定性”两个问题。默认选前者，核对完整问句，再“采用这个问题”。
5. 为体验修改，先选多种划分与重复性检查，点“整理这份方案草案”。聊天摘要说明回答什么、怎么研究、怎样判断、条件与未知事项。
6. “打开方案” → 正常研究材料中的方案审阅 → “修改条件” → 改为固定任务、一个划分规则。系统说明比较因素与工作量收窄，旧草案保留且依据已变化。
7. 整理新草案 → 打开、审阅 → “保存当前方案” → 顶部“下载当前产物”。下载已采纳方案或教学问题/方案/来源包。
8. 与导师继续核对真实数据、预算、权限与细节。可“带着这个思路开始自己的研究”，先补自己的主题条件，只带入公开资料和参考笔记，不确认新项目主线。

另一条有效路线选择单方法的数据差异问题；小范围/多划分两种约束均可用。总共仍为四种计算研究分支，未增加案例数量。

### 硫化物电解质：实验研究设计（仅规划）

1. 案例体验 → 硫化物 v1.1.0。先说明材料传导与完整电池不是同一研究对象，不提供实验操作规程。
2. 默认选“先看材料性能怎样可比”；另一关注点是材料与电池证据的区别。
3. 查看三份来源及不同阅读范围，理解哪些是指定材料的背景，哪些是器件挑战；不能据此直接排名或填入实验参数。
4. 比较“材料传导性能怎样可比”和“体相与界面证据怎样区分”。默认选择前者，复述问题后明确采用。
5. 先选两类对象的可比性审查，整理并打开对应方案讨论稿；检查对象、变量、对照、测量、误差与专业审核。
6. “修改条件” → 限定一个材料体系。新稿减少跨体系比较，保留条件与缺项核对；明确说明改变，不声称完成测量。
7. 审阅新稿 → 保存当前方案 → 从同一个顶部下载入口导出。与导师核对实验室条件、安全及专业可行性；系统到 DESIGN 为止。

另一条路线区分体相与界面证据，两种范围均有独立设计内容。所有路线都不合成材料、不执行实验、不生成结果。

## 4. 教学与正常使用的操作对应

| 用户操作 | 普通研究 | 教学案例 |
| --- | --- | --- |
| 表达需求、追问 | 中央对话，项目内独立会话 | 同一对话和输入框，预置讲解有来源标记 |
| 查看文献 | 研究材料中的文献卡，或文献导入与浏览详细页 | 同一材料组件，来源已预先整理，原文链接可选 |
| 候选与确认问题 | 看到真实建议，明确采纳到研究记录 | 同一候选预览/采纳交互，选中和正式采用分开 |
| 完整方案审阅 | `planReview`，方案正文、关联问题、版本与依据 | 同一 `planReview`，仅生成来源换成预置方案分支 |
| 修改条件、请求修订 | 讨论修改并产生新草案，再手动采纳 | 修改有限教学范围，形成匹配新草案，再手动保存；不调用模型 |
| 下载 | 顶部下载当前产物及指定版本导出 | 同一目录、真实导出接口，保留教学/版本/未验证标记 |
| 开始自己的研究 | 创建独立普通项目与会话 | 原项目保留，新项目只带入参考，不复制教学条件为用户事实 |

没有创建第二套方案数据库、研究主线、聊天系统或独立网站。教学采纳保留原 `/teaching/choices` 原子进度约定，内部使用 `ConversationService.apply(..., _transaction=conn)`，不是在前端模拟成功。普通项目的采纳、材料快照和 DESIGN 边界继续沿用原接口。

## 5. 数据、接口与兼容

- 发布 `fl-heterogeneity/1.1.0.json`、`sulfide-design/1.1.0.json`，原 1.0.0 文件及指纹不变；已有体验不迁移、不重新生成消息。
- 新版包的可审阅 `experience` 字段包括 `scene`、`landscape`、`question_help`、`source_relations`、五类 `faq`、`scope_changes`。新情境/范围是教学设定；事实仍限于原核验来源的实际阅读范围，不新增实测结论或虚构新文献。
- 目录每个案例只提供最新发布版，绑定版本仍由 `load_package(case_id, version)` 读取；校验工具会检查 manifest 的**全部版本**，而不只检查目录中的最新版。
- 进度只增加兼容展示字段：`stage_index`（0–3）、`stage_title`、`stage_why`、`experience`、`question_candidates`；选项 `kind` 区分 `discussion` 与 `operation`。原 `step`、`state_version`、`choices` 和收据机制不改。
- `choices.interest` 只影响关注点解释与候选排序，不自动确认问题或替换项目主线。`choices.scope` 则使用原材料变更机制；相同范围重选不伪造材料修改。
- 共享 `/workspace?include_chat=false` 的论文摘要增加 `authors`、`reading_scope`、`relevance`、`teaching`，不丢旧字段。查看不写库。
- `/api/conversation-capabilities` 增加 `teaching_experience: 1`。开始新版体验前明确检测；没有该能力就提示更新后端，不将任意项目 404 当作版本问题，也不回退混用旧聊天。
- 自由输入继续用原消息接口、稳定 request_id 与现有存储。仅五类常见追问使用对应案例的预置解释，问题与回复一起保存；刷新不再生成。暂停尊重用户意图，未覆盖问题明确说明边界。解释不自动推进、不采纳、不改材料版本。
- 完整方案仍存在原 Suggestion/WorkItem 中。聊天只展示五项摘要；正式保存后“打开方案”定位已保存版，历史版不冒充当前版。
- 旧版历史体验仍可读、查看材料、按原进度继续；不会为它们补写新版聊天。要体验新版讲解，应从目录明确开始 1.1.0，而不是修改原绑定版本。

## 8. 主服务与未验证事项

8001 在本轮开始及结束检查均为 PID 30416；只读能力接口仍没有 `teaching_experience` 字段，说明主后端**未加载本轮代码**。没有启动、停止或重启它。静态文件已修改不等于主后端已更新，新案例入口会准确提示需要更新/重启；需用户另行确认重启后才能在主服务体验新版。

本轮隔离服务仅使用临时数据，验收后关闭；没有修改用户真实项目、调用真实或付费模型、实时检索、训练或实验，也没有提交、推送代码。

尚未验证：真实新手是否理解并认可教学效果；真实模型的普通研究内容质量；公网部署、多用户、实际硬件可行性；Word/PDF 复杂公式转换完整性。导出沿用原能力，实际验收了 Markdown，不宣称修复全部格式。

在用户亲自体验并给出反馈前停止；第七步整体验收尚未开始。
