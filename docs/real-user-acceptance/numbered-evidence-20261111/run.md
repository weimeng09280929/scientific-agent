# r3-261111 证据编号修复与真实验收

本轮复用现有 TokenDance 的 `deepseek-v4.1-flash-1017`，使用 DPR、BPR 公开选段及隔离演练。r2 输入、输出、账本和页面证据只读保留。独立启动器仍限制端点、文本大小、单次输出和每个明确页面操作的网络次数。本轮按用户授权取消累计金额硬上限，启动配置保留累计尝试上限、停止时间和逐次费用记账。

## 根因与实际修改

- r2 方法草案两次完整返回，均在用户事实校验处被拒绝。生成端原来须自行重抄用户原话，很容易丢掉限定。现在计划请求收到当轮范围内的 `user_facts`。项目背景带版本，正式问题带记录身份，近期用户消息仅纳入完整、有效版本，当前请求保留完整原文。模型选择 `fact_id` 后服务端回填完整值和来源，另外提交不一致的正文会被拒绝。已保存条件只能绑定对应项目背景字段。未确认条件继续保持待确认。
- 引文原来由模型逐字重抄，真实回答漏掉了连字符、维度符号和表格中的中间数字。现在只给最终送入模型的正文、开头预览和预编号连续子段编制 `evidence_id`。编号绑定项目、会话、请求、材料版本和内容。阅读、缺口和方案的编号共用原文解析，页号和位置由服务端计算。历史文字引文走原严格路径，旧证据和方案指纹不因新增空字段被重写。
- 伴读选段曾偏向背景词频较高的前页。现在优先覆盖输入、处理阶段和输出线索，分阶段方法优先过程性正文。数字比较同时选表格、明确的指标定义和同页解释，找不到定义时提示不能推断分母。候选缺口和计划优先补选关联论文正文。
- 阅读说明明确锁定数据集、方法变体、指标分母、k、单位及条件。方案在未知算力时拦截一类确定性的硬件可行性承诺，条件化建议仍可保存。引文定位属于确定性检查，数值口径和科学推理仍须独立核对，不能由引用存在直接推断。
- 「修改草案」现在从网页绑定当前会话中仍有效的原草案，生成器收到对应修订目标。新草案保留原问题，导出含修订来源。用户事实编号解析失败直接保留原请求和材料。在隔离真实验收中每个明确页面操作最多一次模型调用，不能隐式消耗第二次修复调用。正常产品的历史证据兼容路径仍保留已有限定的条件修复。

涉及 `core/workspace/evidence_refs.py`、`paper_reading.py`、`guide.py`、`research_coach.py`、`schema.py`、`plan_schema.py`、`plans.py`、`conversations.py`、`web/static/conversation-home.js`、两个隔离验收启动脚本及回归用例。
