## 3. 本轮发现与修复

### 3.1 普通资料导入实际不可发现

主应用已有 `renderUploadCard`，但没有在实际使用的文献页面挂载；另一套未使用页面的上传控件不能解决真实用户入口问题。

已在“文献与资料／文献库”加入折叠的“导入已有文献（PDF / TXT / MD）”，复用现有上传接口。主对话材料面板的“文献导入与浏览”可以到达这里。没有恢复主题文件覆盖操作，没有另建上传系统。新空态不再要求用户先跑旧 research 流水线。

### 3.2 上传内容、解析与证据范围不准确

修复 `web/api.py` 上传处理：

- TXT/MD 原先只对前 5000 字建立片段；现在完整文本分片，开头节选只作显示，不冒充论文摘要或已核验全文。
- PDF 成功解析后原先还可能再次解析；现在一次解析的结果复用，避免重复耗时。
- PDF 解析失败不再把失败说明当作摘要；保存明确 `parse_error`，范围为仅元信息／未读取正文。
- 同名 PDF 使用独立文件名保存，不覆盖前一条论文所关联文件。
- 校验数据库存在、文件名、类型、空内容、UTF-8 后再写入；无效输入不改变项目，缺失数据库不补造空库。
- `reading_scope` 与 `parse_error` 以兼容字段返回；文献页、共享材料面板及指导／方案上下文使用真实读取范围。

没有宣称任意 PDF 均能完整解析。解析能力和片段上限仍沿用既有实现。上传接口本身没有新增 request_id，网络丢失后重新上传仍可能形成另一条导入记录；不要把会话消息的幂等保证扩大到所有文件上传。

### 3.3 快速离开材料页面出现未处理异常

真实浏览器复现：点击“导入／查看论文”后立即进入“文献导入与浏览”，页面中止旧读取，`openMaterial` 的异步异常没有接住，控制台出现 `AbortError: signal is aborted without reason`。

已在材料打开操作内检查当前视图并处理请求中止，其他读取错误仍正常提示。回归测试延迟**真实 GET 响应**再切换页面，确认无未处理异常；没有过滤控制台错误，也没有把页面离开当作服务端取消生成。

### 3.4 方案阅读噪声

方案正文原样保留，只在显示层合并完全相同的通用教学／未验证提示，不删除具体证据缺口、未知设备、期限、预算或审核事项。模板标识、记录／问题编号与修订编号放入折叠详情；下载目录中的短记录编号也改为详情显示，版本号仍直接可见。

引用与关联问题优先显示标题、作者年份；不重写原消息、历史方案、案例发布包或导出正文。普通项目和教学项目使用相同的方案审阅与材料面板。

### 4.3 测试中出现的失败如何处理

不隐藏首次失败：

1. 新增嵌套“版本与技术详情”后，旧浏览器脚本用所有后代 `summary` 定位产生严格模式失败。改为 `:scope > summary`，保留原方案审阅、版本和下载断言；新实例整条方案路径通过。
2. 检索脚本 `/失败/` 误匹配运行中“失败来源”文案，尚未到终态就查找重试按钮；改为匹配明确失败状态。中途失败留下的夹具 mode 也曾影响重跑，明确重置夹具后才验收，不扩大超时或删除重试断言。
3. 新增 PDF 正向解析测试错误传入不存在的区域名 `reading`，按已有契约修正为 `literature`；仍断言仅解析一次、真实片段入库、读取范围到达指导上下文。
4. 文献页导航中止异常是实际产品问题，已修复，并用延迟真实响应的浏览器回归验证；没有通过忽略 `pageerror` 掩盖。
5. 真实验收辅助程序有 SDK 传输计数遗漏、全局日志抑制影响来源分类，以及将 dataclass 当 Pydantic 使用的错误。下节单列其影响，不将这些运行算作真实全链路通过。

## 6. 单独记录：授权后的真实来源与模型试验

用户本轮明确授权一个公开联邦学习临时样例，计划上限为来源 6 次、模型 6 次（含重试）。没有上传私人材料、使用真实用户项目或运行实验。使用当前路由 `deepseek-v4.1-flash`，实测模型网关主机为 `tokendance.space`；没有修改用户配置。

### 6.1 实际观察

| 项目 | 观察 | 如何判定 |
| --- | --- | --- |
| OpenAlex 常规路径 | HTTP 200，约 4.20 秒，取得 4 条公开记录 | 证明这一次请求可达，不证明长期稳定 |
| arXiv 常规路径 | 两次 HTTP 429，约 31.51／29.16 秒 | 来源受限，不能解释为没有相关论文 |
| 有限直连诊断 | OpenAlex HTTP 200，约 3.78 秒；arXiv ReadTimeout，约 32.39 秒 | 没有证明直连可以修复所有来源；没有改变系统默认直连配置 |

### 6.3 验收工具限制与预算记录

首次工具误挂 `httpx` 0.x 计数器，而当前 SDK 使用 `httpx2`。所以首次 JSON 中的 `model_requests: []` **不代表零调用**，无法核实首次含内部重试的精确 HTTP 总数、token 或费用。后来单独记录到一次模型 HTTP 尝试。首次运行涉及查询规划、相关性筛选、现状综合、方案四个逻辑步骤，不能把逻辑步骤数直接当真实请求数。

早期辅助记录中的 `first_run_model_upper_bound: 5` 也是未经验证的估计，**不作为已满足六次上限的证据**。已经停止所有真实调用，未继续追加模型或来源请求；不声称完成请求总数及费用上限审计。后续可复用的显式 opt-in 工具已改用实际 SDK 传输计数，不会随测试或页面读取自动执行；再次运行仍需要新的明确范围，不能据本轮授权继续扩量。
