# 科研对话流程与回答交付修复（2026-10-23）

## 本轮目标

保留原有论文检索、入库、阅读支持、研究缺口、方案及采纳机制，为对话补上明确的步骤入口。
不是另建科研流水线，也不是让用户自己写专业检索词并逐项指挥工具。

用户始终可以自由提问、返回或修改。本步完成建议由系统根据实际条件、材料和本会话讨论给出，
不能按聊天轮数自动认定完成；系统需总结已有信息、保留不确定条件，并提出可操作的下一步。

## 用户能走的路线

| 讨论环节 | 系统做什么 | 用户的明确操作／产物 |
| --- | --- | --- |
| 明确兴趣与条件 | 从已有背景与本会话识别兴趣、条件和未知信息，不反复要求填完整表单 | 讨论后选择进入选题探索；未知设备、期限等可保留待确认 |
| 开始选题探索 | 比较少量切入方向及需要核查的依据，不将宽泛方向当作已确认问题 | 选择重点，再进入论文阅读 |
| 检索入库与论文阅读 | 没有可读材料时打开原有检索范围确认；确认后由原任务调用配置的公开来源并入库。有材料则优先阅读实际摘要／正文片段 | 查看文献与资料；区分元信息、摘要和实际取得的正文，不宣称自动取得所有全文 |
| 研究现状与 research gap | 复用论文、既有报告与缺口材料，比较已有工作、文献局限和待核查设想，不重复发起检索 | 讨论哪些缺口有依据、哪些仍需核查；缺少资料不等于创新 |
| 讨论并确认研究问题 | 将方向收窄成有依据、可设计方法回答的候选问题 | 用原有“采用这个问题”明确确认，不因继续聊天而自动采纳 |
| 形成并审阅研究方案 | 结合已确认问题、真实文献、已知／未知条件，使用已有三类方法方案生成与审阅机制 | 选择方法并发送生成请求；得到草案，修改、明确采纳，再下载对应版本 |

对话上方提供可展开的“科研流程”、当前任务入口及“讨论好了，进入…”按钮。
切换环节本身不调用模型、不检索、不确认研究材料。点击讨论入口才发送明确的用户请求；
若已有未发送草稿，沿用原有确认界面保留草稿，不能静默覆盖。

原有检索任务可能已经自动保存了研究现状整理报告；后面的现状讨论复用它，
不为展示阶段差异重复运行来源调用。检索任务成功、论文入库、方案保存均不代表科研结论得到验证。

## 数据与接口

- 仍以真实主应用 `index.html` / `conversation-home.js` 为入口。
- `ConversationCreate`、`ConversationPatch` 与首次创建接口支持可选 `discussion_step`：
  `conditions / exploration / reading / synthesis / question / design`。
- 显式选择保存在项目 SQLite 既有 `sra_chat_meta` 的 `discussion_step:{conversation_id}` 键；
  不增加另一套方案库或阶段状态表。只读访问不建表、不迁移；历史会话没有该字段仍正常读取。
- `GET /api/projects/{pid}/conversations/{cid}/research-route` 返回讨论步骤、动作说明、
  下一环节与限制、实际可读材料范围、已有报告索引。
- 能力字段 `research_discussion_route=true`；旧后端未声明时不展示新版步骤控制，不能假装新接口已加载。
- 选择属于当前会话，不混入同项目其他对话；同项目正式材料、论文与报告仍共享。
- `entry_stage` 仍是原有进入场景；`discussion_step` 是用户当前选择的讨论任务，
  两者都不代替 `product_stage`、`product_boundary`、`workflow.flow.planReady`。
- 只把精简的讨论投影传给指导模型，不把六套完整按钮文案重复塞入上下文。
- 首次创建和会话创建的原请求哈希保持兼容：未提供新字段时不把 `null` 加入旧身份。
- 方案生成、问题选择、方法选择、建议采纳、版本、来源指纹及导出沿用原接口，仍止于 DESIGN。

## 回答失败的原因与处理

真实失败记录表明模型请求和结构解析已经成功，但一个采纳按钮无法绑定当前会话有效草案，
旧代码因此把整段回答判为失败。失败时未保存原始模型操作，不能据此推断它究竟指向旧草案还是笔记。

现在先保留原有正文、引用、研究建议和方案校验，再独立校验每个操作绑定：

- 引用伪造、非法操作类型、无效研究建议或方案仍失败，不降级成安全成功。
- 合法操作类型但无效目标被拒绝，不执行；独立通过校验的回答可以交付。
- 在助手消息的 `delivery_warnings` 持久记录“部分操作未提供”，刷新仍可查看；
  调用审计记录 `action_rejected:{type}`。不通过重新请求整段模型回答来修复单个按钮。
- 对声称已采纳／已保存／已启动、却没有有效操作的回复保留拒绝保护。
  这是有限的确定性规则，不宣称能够识别所有自然语言误导。
- 合法建议仍只是未采纳草案。请求重放不重复新增助手消息、建议或正式研究记录。
- `suggested_replies` 与操作总数继续不超过四项；普通讨论不要求凑出正式研究问题。

另外，步骤验收发现“讨论，不检索”“不重复检索”“不重新检索”会被误判为明确授权。
已在原意图分类器增加否定识别；没有改动来源适配器、检索配额、筛选或 research gap 引擎。
讨论环节的保守推荐也优先服从用户选择，不因旧 `entry_stage=literature` 又退回索要检索词。
