# TokenDance 论文理解六题对照

## 范围与请求约束

本轮按用户授权，在同一 TokenDance Chat Completions 端点对照既有 `deepseek-v4.1-flash-1017` 和 `deepseek-v4-pro`。只重放已归档 B 组 D1、D2、B1、B1f、B2、G1，材料为 DPR、BPR 公开论文选段。六份发送体保留全部 `messages`、证据编号、温度 0.2、`json_object` 和 8192 输出 token，仅替换 `model`。使用独立账本，每题最多一次，共最多六次，无累计金额硬上限。实验过程没有改变选段、提示词和网站默认路由。

- 受限入口 [tools/compare_paper_models.py](../tools/compare_paper_models.py) 固定模型、端点、六个题号和四份归档 SHA-256。发请求前检查方法、端点、既有 TokenDance 鉴权、104000 字节上限和完整序列化请求体。普通运行只检查归档，真实调用须显式使用 `--allow-live`。
- 每题先以 SQLite 主键占用一次，使用现有 `AuditScope` 记录网络尝试及总次数。重复执行、请求结果未知或进程重启均不能补发已占用题目。HTTP 客户端关闭重试和重定向。旧 Flash 入口保持原有限制。
- 仅使用独立命令行进程，未启动隔离网站、未写入正式项目。保留模型可见的原始回答、结束原因、用量与响应身份，移除隐藏推理正文和凭据。

## 评阅方法

逐题按原始 [冻结判据](paper-understanding-accuracy/criteria.md) 核对事实、证据边界、引文、可理解性和结构。回执先移除模型名、延迟和费用，逐题随机分配甲、乙。依据编号用各题原入模文本解析，检查定位后再人工判断它是否支持结论。评阅人接触过旧 Flash 回执，可能从措辞识别旧回答。

严格通过要求题目所问关键事实完整准确、范围表达可靠、引文支持主要结论，并符合输出契约。材料不足题以判断边界和可行的核查路径为目标。
