# 第一批修复：回复交付、失败恢复与输入保护

依据：`user-experience-audit-20261022.md` 的 01、02、03、14、15、30、31、32，以及同目录的请求、调用记录和截图。验收基于本地未提交工作区，不是发布版本。只处理第一批，没有改造首页／侧栏、扩充领域或进入实验与写作。

## 1. 用户现在能得到什么

- 合法的科研回复不会仅因“讨论选项和操作合计超过四项”而整段失败；超限只做确定的展示规范化，所有引用、建议、资源与动作仍先校验。
- 方案条件保留原始引用，只容忍空白和全半角 ASCII 的排版差异，不将上标、单位或圈号数字折叠成普通数字。其他改写不会被直接当成事实；特定摘录错误最多进行一次模型修复，仍须重新通过完整校验。含否定或待确认的条件不能截成肯定事实。
- 普通指导与方案生成的等待提示区分；原请求进入终态后移除对应旧等待提示；创建失败不再继续显示正在创建，输入仍在。
- 笔记按项目保存本机草稿，支持 Ctrl/Cmd+Enter，切页／刷新能恢复。保存针对提交快照，旧响应不再清空其他项目或保存后新输入的内容。

**本轮三种真实回复均已交付，并实际完成方案审阅、草案下载和测试者手动采纳。** 这是一个公开联邦学习样例的交付验证，不等于所有模型、课题或研究方法均通过内容质量验收，更不证明方案科学正确。

### 历史方案失败：能确定与不能确定的部分

旧记录能确定 HTTP 成功、结构解析成功，随后条件依据校验失败；旧错误没有字段路径，也没有保存原始失败方案。因此**不能断言历史失败一定是资源字段或一定只是空格问题**。

本轮检查并测试了 brief、已确认问题、本会话用户历史三条条件路径；未发现这些路径在当前方案上下文投影中被删除。现在失败审计使用 `condition:<field>:<reason>`，可区分：

- 引用不在本次用户依据：不替用户补事实，不自动修复为成功。
- 引用存在但值不是原文摘录：仅模型模式允许一次有界条件修复，提示按已有原文重新摘录；再次失败即失败。
- 未知条件填写了确定值：拒绝，要求待确认。
- 引用包含否定／待确认但值删掉限定：保守要求保留完整原条件；不能用“没有GPU”作为“GPU可用”的依据。一次修复仍失败就拒绝交付。
- 非法结构／引用／关联：继续拒绝，不用展示截断藏掉问题。

所有修复结果重新执行引用、项目归属、动作白名单、关联问题、条件、精确参数及范围检查。没有自动采纳，没有保存部分方案作为成功结果。失败保留用户消息和已有材料；显式重试使用原 request_id、重建当前依据，不重复插入用户消息。

## 3. 修改范围与契约

主要代码：

- `core/workspace/conversations.py`：写入前校验所有内容；有界条件修复及最终失败审计；不在错误正文附异常类名；截断反馈说明没有保存不完整草案。

### 预算与审计

首次输出额度：普通指导 4096、问题候选 6144、明确长方案 12000 token；推理与 JSON 共享额度。方案上下文继续排除重复旧方案与无关历史材料，reply 以简短交付为主，正文从已校验结构渲染，避免重复输出。

截断不作为有效回答；注册表最多一次预算修复／结构修复。条件修复另有最多一次限制，仍计入实际网络审计和调用闸门，不能无限重试。

审计可区分 `display_validated`、`display_normalization`、`model_repair:truncated_output`、`model_repair:invalid_structure`、`condition_repair:<field>`、`final_failure:<类型/条件原因>`。这些是处理事件，不是模型请求次数；实际次数只按 network 记录计算。错误细节在展开的调用记录中查看，不把模型原文、密钥或认证头写入常规调用审计。

## 6. 限制与后续注意

- 新手指导真实首请求仍可能推理占满输出额度，本次发生一次截断，总等待约 75 秒；现在可以识别、修复、查询与交付，但不能承诺低延迟或所有请求成功。
- 真实样例只验证联邦学习的已有摘要路径；理论研究、实验设计、其他模型、实时来源的真实质量未在本轮重验。当前问题仍较宽，CPU 可行规模、具体资料权限与参数须与导师核对；结构及引用检查不证明科学正确。
- 条件处理不是通用语义蕴含判断，不接受所有同义改写；不能可靠对应时拒绝或待确认。旧失败方案未留存具体字段，这一历史诊断缺口无法倒推补齐。
- 笔记草稿在当前浏览器、当前设备 localStorage，不是服务端已保存笔记；清除浏览器数据会删除本机草稿。笔记网络错误可能是响应丢失，因此提示先核对历史再重试，不宣称笔记 POST 已获得跨网络的 exactly-once 保证。
- 外部模型调用也没有 exactly-once 保证；只保证本地消息、建议与正式材料按既有请求和事务机制不重复。
- 仅真实下载并检查 Markdown；复杂 Word/PDF、真实手机键盘、跨浏览器设备同步未验证。
- 本轮隔离服务使用后已不再监听（8063、8064 均检查连接被拒绝）；8001 同样未监听，未被本轮启停，用户主服务没有因此自动加载新后端。临时测试目录保留供复核，路径见验收 JSON，不属于用户真实项目。未提交／推送／部署。
- 用户本人尚未对这次修复体验签收；自动化和测试者操作不替代用户认可。
